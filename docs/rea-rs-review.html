Fidelity

Shared idea: a local stdio MCP and a JSON CLI for static inspection of native binaries. That slice is wider than the first review (five tools then, fourteen now). It covers function discovery on x86, x86_64, arm64, and Thumb, a direct call graph, WASM sections, Go 1.18+ build info, Mach-O dylibs, UUID, build version, a code-signature flag, and fat architectures, a PE directory skim plus a CLR header and stream directory, ELF interpreter and build-id, a SQLite header and sqlite_schema, and a real LE fixup pass. It is still a different program. Tool names do not match. There is no Evidence record, no provider session, and the protocol stays 2024-11-05 with text results. LE / DOS/4GW is original work. Upstream has no Watcom LE contract.

What this tree does on its own

  • One Target for Mach-O, ELF, PE, and LE, with virtual-address to file-offset translation. Fat Mach-O picks a host slice.
  • LE is recognized before goblin. Fixup page bases use the object page map. A bad page-table slot or a short record returns Err.
  • Function bodies follow a forward jmp or arm64 b, and stop at ret, retf, Thumb bx lr, Thumb pop of pc, and an indirect or backward jump. rea callgraph on WAR.EXE reports 742 functions and 1,962 edges after the Thumb arms, the same as before them. The Warcraft note still says 2,386 call edges. That older tally was not what this CLI printed.
  • The Warcraft note in docs/warcraft-1-demo-re.md matches the corrected record order and the 8,457 / 0x109eb check.

LE fixup review — findings, then the fix

The four bugs, the suggestion, and the nit below were the review of commit 2e7687b. They are fixed in this working tree. The walker was replaced, load_le propagates apply_fixups, and WAR.EXE was re-checked. The notes stay so the old failure mode is readable.

Commit 2e7687b taught LeImage::apply_fixups to rewrite internal relocations. A single internal 32-bit fixup on an identity page map (the Warcraft demo) could land correctly. The first walker did not follow the record layout it cited, and a slipped cursor wrote later records into the image. synthetic() left the fixup tables at 0, so that path returned Ok(0) and hid the bugs. Tests now cover an internal 32-bit write, a source list whose offsets follow the target tail, a 16-bit object-relative store, an import that must not eat the next internal record, and an oversized page map that returns Err.

fixed

Source lists were parsed before the ordinal and target

was crates/rea-core/src/le.rs, source-list flag 0x20

The count replaces the single i16 offset. The offsets come after the ordinal and the target, not before them. The old code read the offsets immediately, so the ordinal and target were taken from the list and the rest of that page shifted.

fixed

Skipped records did not consume their tail

was crates/rea-core/src/le.rs, import and selector tails

Imports, a bad object number, and selector fixups used to continue without finishing the record. The next iteration treated the middle of that record as a new fixup. Bit 0x08 is not a chain. load_le used to drop the Result. Short reads now return Err, and the loader propagates it.

fixed

Page bases were keyed by file page, then indexed by logical page

was crates/rea-core/src/le.rs, page_vaddr

Those numbers match only for an identity map, which WAR.EXE has. The walker now uses the object page map, the same way translate does. An oversized mapsize returns Err instead of panicking. Stores go through pages.translate one byte at a time.

fixed

16-bit offset fixups stored a truncated linear address

source type 5

Source type 5 stores the object-relative offset, and only when it fits in a u16. The old code wrote the low 16 bits of object.base + offset. Source type 7 still stores the linear u32. Source type 8 stores (base + rel).wrapping_sub(src_vaddr + 4).

fixed

The header comment, the tests, and the stats example

le.rs module comment, synthetic fixtures, examples/le_fixup_stats.rs

The module comment now says internal fixups are in scope and that entry bundles and iterated pages are not. The stats example no longer clones an unused buffer, and the 4-byte read at 0x109eb is bounds-checked.
